V1 implements backend declarations, discovery/status, profile-local named Boxery disk-image definitions and explicit CLI/tool selection. Further work, NOT implemented:
- Adapter-validated direct native sources (provider image/snapshot refs, Lima definitions, disk paths), only through operator-defined templates.
- Recipe-driven named preparation reusing existing image layers/build-base and the application-profile plan.
- Independent template ownership, versioned candidates, atomic publication, durable build/recovery and dependency-aware retention; no unsafe automatic GC.
- Rehome CH RAM builder/cache behind named CH template preparation; preserve exact disk/RAM pairing and keep arbitrary user images disk-only.
- Live provider conformance, real privileged TAP/COW and reboot/upgrade matrices, security review and honest cold/warm/concurrent/cost benchmarks.

Do not introduce a universal snapshot format or silently weaken networking/guest contracts. Preserve existing defaults and native backend mechanisms.
